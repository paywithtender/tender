Tender docs

Tender is an x402 payment rail on Robinhood Chain. APIs get paid in exact USDG. Agents pay with whatever token they hold, and Tender swaps it on Uniswap inside the same transaction.

I run an APICharge per call in USDG, and accept any token if you want. I use an AI appGive Claude, Cursor or any MCP client a wallet that can pay. I build agentsPay x402 APIs from code with the token your agent holds.

Tender is a standard x402 v2 facilitator for Robinhood Chain (eip155:4663). If you already use Coinbase's @x402/* packages, point them at https://facilitator.paywithtender.com and you're done.

Accept payments

With Coinbase's x402 SDK (USDG)

Use the stock exact scheme. Tender covers the gas, within daily limits, and charges no fee.

server.ts
import { paymentMiddleware, x402ResourceServer } from "@x402/express";
import { HTTPFacilitatorClient } from "@x402/core/server";
import { ExactEvmScheme } from "@x402/evm/exact/server";

const server = new x402ResourceServer(
  new HTTPFacilitatorClient({ url: "https://facilitator.paywithtender.com" })
).register("eip155:4663", new ExactEvmScheme());

app.use(paymentMiddleware({
  "GET /weather": { accepts: [{ scheme: "exact", price: "$0.01", network: "eip155:4663", payTo: "0xYourAddress" }] },
}, server));

Accept any token

Add @paywithtender/x402 and a tender-swap entry next to exact. Agents holding ETH, $TENDER or any coin with a Uniswap route can now pay. You still receive exactly the price in USDG, and the agent pays the swap fee.

Terminal
npm install @paywithtender/x402
server.ts
import { TenderSwapServer } from "@paywithtender/x402";

server.register("eip155:4663", new TenderSwapServer());

// in the route config
accepts: [
  { scheme: "exact",       price: "$0.01", network: "eip155:4663", payTo: "0xYourAddress" }, // USDG
  { scheme: "tender-swap", price: "$0.01", network: "eip155:4663", payTo: "0xYourAddress" }, // any token
]

With the Tender SDK (Express)

If you aren't on the x402 SDKs, tenderPaywall does both schemes in one middleware.

Terminal
npm install @paywithtender/sdk viem
server.ts
import express from "express";
import { tenderPaywall } from "@paywithtender/sdk";

const app = express();
app.use(tenderPaywall({
  payTo: "0xYourWallet",
  facilitator: "https://facilitator.paywithtender.com",
  routes: { "GET /premium": { price: "$0.05", description: "Premium data" } },
}));
app.get("/premium", (req, res) => res.json({ data: "…" }));

Unpaid requests get a 402 with the payment options. Paid requests are verified and settled on-chain before your handler runs.

Pay from an agent

From Claude, Cursor or any MCP client

The MCP server gives your AI four tools: check_coin, quote, wallet and pay. Add it to your client's config (for Claude Desktop, claude_desktop_config.json):

claude_desktop_config.json
{
  "mcpServers": {
    "tender": {
      "command": "npx",
      "args": ["-y", "@paywithtender/mcp"],
      "env": {
        "TENDER_PRIVATE_KEY": "0xYOUR_AGENT_WALLET_KEY",
        "TENDER_PAY_WITH": "0xTOKEN_THE_AGENT_HOLDS",
        "TENDER_MAX_PER_CALL_USD": "0.50",
        "TENDER_DAILY_LIMIT_USD": "5"
      }
    }
  }
}
Use a fresh wallet that holds only what you're happy for the agent to spend. The key stays on your machine: payments are signed locally and only the signature is sent. Leave out TENDER_PRIVATE_KEY to run read-only.

Then try it on Tender's own paid API. Ask your AI: "Pay https://facilitator.paywithtender.com/api/gas with my bag." It costs $0.01 plus gas. All settings are in the MCP server README.

With Coinbase's x402 fetch

agent.ts
import { wrapFetchWithPaymentFromConfig } from "@x402/fetch";
import { TenderSwapClient } from "@paywithtender/x402";
import { privateKeyToAccount } from "viem/accounts";

const account = privateKeyToAccount(process.env.AGENT_KEY);
const pay = wrapFetchWithPaymentFromConfig(fetch, {
  schemes: [{ network: "eip155:4663", client: new TenderSwapClient({ account, payWith: "0xTokenYouHold" }) }],
});

const res = await pay("https://api.example.com/data");

Agents that hold USDG can keep using the stock ExactEvmScheme client with no changes.

With the Tender SDK

agent.ts
import { wrapFetchWithTender } from "@paywithtender/sdk";

const pay = wrapFetchWithTender(fetch, {
  account,                     // viem LocalAccount
  chain: robinhood,            // chain id 4663
  payWith: "0xAnyLiquidToken", // leave out to pay in USDG
  maxUsdgPerCall: 1_000_000n,  // never more than $1 per call
  maxFeePerCall: 50_000n,      // skip if fees top $0.05
});

const res = await pay("https://api.example.com/premium");

First payment with a new token

Each token needs a Permit2 approval before its first payment. The MCP server sends a capped one for you: enough for 7 days at your daily limit (change it with TENDER_APPROVAL_DAYS), renewed when it runs low. TenderSwapClient approves once. With the Tender SDK, call ensurePermit2Approval, and pass amount to cap it. If the wallet has no ETH for gas, Tender covers its first approval.

agent.ts
import { ensurePermit2Approval, ROBINHOOD } from "@paywithtender/sdk";

await ensurePermit2Approval({ wallet, publicClient, token, permit2: ROBINHOOD.permit2, facilitator: "https://facilitator.paywithtender.com" });

Fees and limits

Paying withTender feeGas
USDG, standard exactNoneCovered by Tender, within daily limits
USDG, tender-swapNonePaid by the agent, quoted up front
$TENDERNonePaid by the agent, quoted up front
Any other token0.5%Paid by the agent, quoted up front
  • The API always receives the exact price. Fees come from the agent's side.
  • Every fee is quoted before the agent signs. The contract caps the fee at 1% and the gas part at 1 USDG.
  • Unused input is refunded to the agent in the same transaction.
  • Standard exact payments start at $0.001. Tender covers gas for up to 30 of them per payer per day.

Which tokens work

Any token with a Uniswap route to USDG on Robinhood Chain, including ETH and Pons coins once they graduate. Tender refuses a payment when liquidity is too thin to swap at a fair price.

Check any coin at paywithtender.com/check: paste its contract address to see if it's spendable and what a payment costs in it. The check_coin MCP tool and the /quote endpoint give the same answer.

Facilitator API

Base URL: https://facilitator.paywithtender.com. It follows x402 v2, so the x402 SDKs and tenderPaywall call it for you. You only need these endpoints if you're building your own client.

EndpointWhat it does
GET /supportedSupported schemes (exact, tender-swap), network and signer addresses.
POST /quoteWhat paying an amount costs in a token. Body: { "tokenIn": "0x…", "amount": "10000" }, where amount is USDG with 6 decimals ($0.01 = 10000). Returns the fee breakdown, estimated and maximum input, price impact and expiry.
POST /verifyChecks a signed payment against its requirements without sending anything.
POST /settleSimulates, then settles the payment on-chain. Returns the transaction hash.
POST /sponsorOne-time gas for a wallet's first Permit2 approval. Body: { "payer": "0x…", "token": "0x…" }.
GET /feedTotals and the latest 50 settled payments.
GET /healthzStatus and relayer address.

Tender API

Tender runs its own paid endpoints, built with Tender. They're useful for testing a client against real mainnet payments. Each call costs $0.01 in any token.

EndpointReturns
GET /apiFree index of endpoints and prices.
GET /api/gasRobinhood Chain gas price, ETH price and what a transaction costs in dollars.
GET /api/token?address=0x…A token's price, market cap, and whether it's spendable on Tender. Invalid addresses are refused before you pay.

Security

  • The agent's signature fixes the merchant, amount, fee and resource, so nobody in between can redirect a payment.
  • Every settlement is simulated before it's sent. If the swap returns less USDG than the price, the whole transaction reverts.
  • The contract holds no funds between transactions. Only allowlisted relayers can settle, and only allowlisted routers can be called.
  • The owner can pause the contract and set fees, but the fee is hard-capped at 1%.
The contract has not had an external audit. Payment sizes are capped on-chain while it runs in production.
